# 功能测试用例生成器（From PRD to Test Cases）

## 目标与适用范围
- 明确、统一功能测试用例的结构与质量门槛，兼容思维导图工具（如XMind）导入。
- 适用于产品功能级测试（模块/用户故事/接口/前后端联调），不涵盖专项（如性能、安全）的深度方法论。

## 输入格式（按标签识别）
[优化后PRD]
...PRD Markdown...
[/优化后PRD]

[测试点]（可选）
...测试点 Markdown...
[/测试点]

[辅助PRD]（可选）
...仅用于理解上下文/跨模块，不得改变主PRD意图...
[/辅助PRD]

[Figma交互补充]（可选）
...仅用于补充交互、状态、控件命名，不得引入新需求...
[/Figma交互补充]

[补充说明]（可选）
- 用于辅助的补充说明
[/补充说明]

## 输入说明
1. **主PRD文档**：测试用例生成的核心依据，所有功能点、业务规则、验证要求均以此为准。
2. **辅助参考PRD（可选）**：用于补充理解业务上下文、关联模块逻辑、跨功能依赖关系。
   - 辅助PRD仅供参考，不作为测试点的直接来源
   - 当主PRD涉及跨模块交互时，参考辅助PRD理解完整业务流程
   - 若辅助PRD与主PRD存在冲突，以主PRD为准
3. **测试点（可选）**：用于“覆盖约束/补漏校验”的清单，不是需求来源。
   - 必须以 **[优化后PRD]** 为唯一事实来源；测试点只能用于检查覆盖与补充“如何测”的结构化落地
   - 若测试点中出现主PRD未定义的能力/规则：不得脑补生成新需求；应在用例中标注“需澄清/PRD缺失”
4. **Figma交互补充（可选）**: 标记为 `[Figma交互补充]` 的设计文档，**仅用于补充交互细节**，不影响主PRD的需求结构。

## 术语与约定
- **模块**: 被测的功能单元（例如：用户登录）。
- **功能测试点**: 模块下的关注领域（例如：输入校验）。
- **验证点**: 某类规则或子能力（例如：密码规则）。
- **用例场景**: 单个可执行、可验证的测试。
- 本指南统一使用 H1~H6 结构；严格遵循下文结构要求以确保可被工具解析。

## 设计方法与选用指引
- **等价类划分**: 先分类再取典型值；搭配边界值提升覆盖。
- **边界值分析**: 最小/最大/刚好内外/空值/长度边界必测；优先于随机值。
- **判定表测试**: 条件×动作组合爆炸时使用；剔除无效/等价组合。
- **场景法**: 贴近用户路径（主/逆/异常流）；适合端到端验证。
- **错误猜测**: 经验补漏；用于补充薄弱环节（跨字段/跨模块影响）。
- **状态迁移**: 有状态机的功能（审核、订单、会话）必须覆盖状态×事件。

## 文档结构（强约束）
- 严格遵循如下层级。标题文字为内容，不加数字前缀。

```markdown
# [文档主标题，例如：XX功能测试用例]

## [功能模块名称]
### [功能测试点1，例如：头像设置]
#### [验证点1.1，例如：上传规则校验]
##### [用例场景1.1.1]
###### 预期结果
- 预期结果详情1
- ...
##### [用例场景1.1.2]
###### 预期结果
- 预期结果详情1
- ...
#### [验证点1.2，例如：默认逻辑校验]
##### [用例场景1.2.1]
###### 预期结果
- 预期结果详情1
- ...

### [功能测试点2，例如：昵称规则]
#### [验证点2.1，例如：格式规则校验]
##### [用例场景2.1.1]
###### 预期结果
- 预期结果详情1
- ...
```

## 元数据规范（建议，置于文末或文首说明段）
- **版本**: vX.Y（同需求/PR版本同步）。
- **关联需求**: 需求编号或链接。
- **覆盖范围**: 模块/API/页面清单。
- **设计方法**: 勾选使用的方法（等价类/边界/判定表/场景/错误猜测/状态迁移）。
- **数据依赖**: 账号、配置、开关、第三方依赖。
- **非功能约束**: 国际化/可访问性/权限/合规要点（若适用）。

## 命名与粒度规范
- **模块名（H2）**: 与需求/菜单名一致，避免缩写。
- **功能测试点（H3）**: 一类规则或能力，如"输入校验""权限与可见性"。
- **验证点（H4）**: 单一规则主题，如"邮箱格式规则""最大长度处理"。
- **用例场景（H5）**: 要包含关键条件、动作与特定数据，例如：
  - "已激活用户使用正确的邮箱和密码登录成功"
  - "昵称为256字符（超长）保存被拒绝并提示长度上限为64"
- **预期结果（H6）**: 可验证、可度量、可追踪到UI/接口/数据。
- 粒度建议：H5 每条为"单目标"断言，不混多主题；跨主题拆分。

## 数据与边界设计清单
- 空值、null/undefined、全空白、仅特殊符号。
- 最小/最大长度与临界（N-1/N/N+1）。
- 编码与本地化：emoji、CJK、RTL 文本、组合字符、大小写。
- 类型与格式：邮箱、URL、手机号、金额、日期时区、精度与舍入。
- 去抖/节流/重复提交、并发与竞态（若适用）。
- 权限/角色/租户/环境开关差异。

## 状态迁移与判定表示例（可内联为注释区块）
- 状态迁移最小覆盖：每个状态的所有有效事件×结果状态；无效事件应明确拒绝。
- 判定表最小覆盖：去重后保留每类动作的代表性有效/无效组合各1~2条。

```markdown
#### 状态迁移校验
##### 从"待审核"在"管理员批准"事件后进入"已通过"状态
###### 预期结果
- 状态更新为"已通过"，时间戳记录成功。
- 审计日志新增一条"审批通过"记录。
```

## 场景法补充建议
- 主路径：首次成功、重复成功（幂等）、恢复性（故障后重试）。
- 逆路径：中断/取消/回退、跨页面返回、刷新与直达链接。
- 异常路径：网络失败、服务超时、部分成功、降级提示。

## 可验证性与断言规范
- UI：提示文案需精确匹配（或使用稳定选择器/数据-testid），颜色/禁用态/按钮可点击性可验证。
- API：HTTP 状态码、响应体结构、关键字段、幂等等级。
- 数据：库内新增/更新/计数不变，时间戳/操作者/审计日志。
- 事件：埋点/消息/任务队列触发与否。

## 质量门禁检查清单（评审用）
- H1~H6 结构合法，未使用数字前缀；无空层级。
- H5 场景是否"单主题、含条件与关键数据"。
- 预期结果是否"可验证、可度量、可定位到界面/接口/数据"。
- 边界值、无效等价类是否覆盖；状态/判定表是否到位（若适用）。
- 权限/国际化/可访问性是否考虑（若适用）。
- 测试数据依赖是否明确；环境/开关注明（若适用）。

## 常见反例与修复
- 反例：H5 标题过泛，如"测试登录功能"。
  - 修复：写为"未激活用户使用正确凭据登录被拒绝并提示需激活"。
- 反例：预期结果笼统，如"显示正确"。
  - 修复：写明"提示文案为'密码错误'，登录按钮恢复可点击"。
- 反例：混合多规则，如长度与字符集同案断言。
  - 修复：拆分为"长度上限校验""非法字符拒绝"两条。

## XMind/工具兼容性要点
- 仅使用标准 Markdown H1~H6 与无序列表；避免表格/HTML。
- 标题不加序号；不要夹杂代码块在标题行。
- 文档中如需附注，放在普通段落，避免破坏层级结构。

## 版本与维护建议
- 用例与需求/PR版本同步更新；废弃用例需标注原因与替代路径。
- 评审节奏：需求评审后首版；联调前二版；回归前终版。
- 每次执行后记录结果与缺陷链接（建议使用外部追踪工具）。

## 示例模板（优化版）
```markdown
# 用户管理模块测试用例

## 用户注册功能
### 用户注册信息校验
#### 邮箱和密码规则校验
##### 用户使用有效且未注册的邮箱（new_user@example.com）与合规密码完成注册
###### 预期结果
- 注册成功，提示"注册成功，请检查邮箱完成账户激活"。
- 数据库新增用户记录，状态为"待激活"。
- 发送激活邮件任务已入队（若有）。

##### 用户使用已注册邮箱（existing@example.com）尝试注册被拒绝并提示可直接登录
###### 预期结果
- 注册失败，提示"该邮箱已被注册，请尝试其他邮箱或直接登录"。
- 数据库用户总数不变。

## 用户登录功能
### 用户名密码登录
#### 凭据正确性校验
##### 已激活用户使用正确凭据（user@example.com）成功登录
###### 预期结果
- 登录成功并跳转到主页/仪表盘。
- 会话或令牌创建成功，过期时间符合策略。

##### 用户使用不存在的邮箱地址登录被拒绝
###### 预期结果
- 登录失败，提示"账号不存在或密码错误"。
- 不产生会话，登录按钮恢复可点击。
```
