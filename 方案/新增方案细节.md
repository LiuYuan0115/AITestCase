### 第一部分：对建议的深度点评与接纳

#### 1\. 关于“上下文注入” (Context Injection) - **⭐⭐⭐⭐⭐ (关键)**

  * **评价：** 这是最重要的建议。没有这一步，AI 就是在“盲猜”。
  * **完善点：** `accessibility.snapshot()` 是个极佳的选择，因为它过滤掉了大量无用的 `div` 嵌套，只保留交互元素。
  * **我的补充：** 为了防止 Token 爆炸（复杂网页的 Accessibility Tree 依然很大），可以引入\*\*“视口裁剪”\*\*策略。只发送当前屏幕（Viewport）内的元素给 AI，如果 AI 觉得找不到，再滚动屏幕并发送下一屏的数据。

#### 2\. 关于“Tab 页同步” (Target Synchronization) - **⭐⭐⭐⭐⭐ (致命)**

  * **评价：** 这是一个典型的工程坑。`pages[0]` 在开发环境（通常只开一个 Tab）没问题，但在用户环境必挂。
  * **我的补充：** 除了匹配 URL，最好生成一个唯一的 `session_id`。插件生成 ID 传给后端，后端在 `p.chromium.connect_over_cdp` 后，可以通过执行一段简单的 JS (`window.my_agent_id = 'xxx'`) 来标记并锁定正确的 Page 对象。

#### 3\. 关于“流式输出” (Streaming) - **⭐⭐⭐⭐ (体验)**

  * **评价：** 长任务必备。FastAPI 的 SSE 实现非常简单，前端用 `EventSource` 接收。
  * **我的补充：** 流式输出不仅要输出文字，还可以输出\*\*“中间状态截图”\*\*。比如 AI 点击了按钮，立刻截一张小图通过 Base64 流回传给插件侧边栏，让用户有“看着它干活”的安全感。

#### 4\. 关于“安全性” (Security) - **⭐⭐⭐⭐ (风控)**

  * **评价：** 这是一个很容易被忽视的红线。
  * **实施细节：** 在 FastAPI 中配置 CORS 时，`allow_origins` 应该严格填入 `["chrome-extension://<你的插件ID>"]`。

### 第二部分：我还能补充什么？（进一步完善）

除了上述 5 点，想要做一个真正能用的“自动化测试 Agent”，还需要解决以下 3 个痛点：

#### 6\. 可视化反馈机制 (Visual Feedback / Highlighting)

  * **问题：** 用户看着页面，不知道 AI 到底想点哪里，心里没底。
  * **方案：** 在 Playwright 执行 `click` 之前，先注入一段 JS，给目标元素加一个**红色的高亮边框 (border: 2px solid red)**，停留 500ms，然后再点击。
  * **价值：** 极大地增强了工具的“可解释性”和“调试感”。

#### 7\. 错误自愈机制 (Self-Correction Loop)

  * **问题：** 页面加载慢，AI 点击时元素还没出来，报错了怎么办？
  * **方案：** 不要在报错时直接抛出异常给用户。而在 Python 端捕获异常，把错误信息（如 `TimeoutError`）喂回给 LLM，让 LLM 决定是“等待 2 秒”还是“尝试另一个 Selector”。
  * **架构变更：** 这是一个 `Think -> Act -> Observe -> (Error) -> Re-Think -> Act` 的循环。

#### 8\. 元素定位的鲁棒性 (Robust Selectors)

  * **问题：** LLM 生成的 CSS Selector 经常不准（比如 `#root > div > div:nth-child(3)`），页面稍微一变就挂。
  * **方案：** 提示 LLM 优先使用 **语义化定位**（如 Playwright 的 `getByRole('button', {name: 'Login'})`）或者 **文本定位**，而不是脆弱的 CSS 路径。

import json
from fastapi import FastAPI, Body, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from playwright.sync_api import sync_playwright
from openai import OpenAI

app = FastAPI()
client = OpenAI(api_key="YOUR_KEY")

# 1. 安全性：严格限制 Origin (替换为你真实的插件ID)
EXTENSION_ID = "chrome-extension://abcdefghijklmnop" 
app.add_middleware(
    CORSMiddleware,
    allow_origins=[EXTENSION_ID, "http://localhost:3000"], # 开发时允许 localhost
    allow_methods=["*"],
    allow_headers=["*"],
)

# ================= 核心工具集 (原子能力) =================

def get_page_context(page):
    """获取页面状态：URL, 标题, 和精简的可访问性树"""
    snapshot = page.accessibility.snapshot()
    # 简单的清理逻辑，防止 Token 溢出 (生产环境需要更复杂的裁剪)
    tree_str = json.dumps(snapshot, ensure_ascii=False)[:6000] 
    return f"Current URL: {page.url}\nTitle: {page.title()}\nAccessibility Tree:\n{tree_str}"

def locate_target_page(browser, target_url):
    """解决 '找错人' 问题：根据 URL 找到对应的 Tab"""
    for context in browser.contexts:
        for page in context.pages:
            # 简单的模糊匹配，防止 url 参数导致的匹配失败
            if target_url.split('?')[0] in page.url:
                return page
    return None

# 定义通用的原子操作工具
tools_schema = [
    {
        "type": "function",
        "function": {
            "name": "perform_action",
            "description": "在页面上执行操作。注意：必须根据 Accessibility Tree 中的 name 或 role 来定位。",
            "parameters": {
                "type": "object",
                "properties": {
                    "action": {
                        "type": "string",
                        "enum": ["click", "fill", "goto", "screenshot"],
                        "description": "要执行的动作"
                    },
                    "selector_name": {
                        "type": "string",
                        "description": "目标元素的名称 (Name) 或 文本内容 (如果是输入框则是 Placeholder/Label)"
                    },
                    "selector_role": {
                        "type": "string",
                        "description": "目标元素的角色 (Role)，如 button, link, textbox"
                    },
                    "value": {
                        "type": "string",
                        "description": "如果是 fill 操作，填入的内容"
                    }
                },
                "required": ["action"]
            }
        }
    }
]

# ================= 业务逻辑 =================

@app.post("/api/run_test")
def run_test_agent(payload: dict = Body(...)):
    user_prompt = payload.get("prompt")
    target_url = payload.get("url") # 插件必须传这个过来
    
    if not target_url:
        return {"error": "无法获取当前 Tab URL"}

    with sync_playwright() as p:
        try:
            # 连接 CDP
            browser = p.chromium.connect_over_cdp("http://localhost:9222")
            
            # 1. 锁定目标页面
            page = locate_target_page(browser, target_url)
            if not page:
                return {"error": "未找到对应的浏览器标签页，请确保 Chrome 已打开且 URL 匹配"}

            # 2. 获取页面上下文 (解决盲操问题)
            page_context = get_page_context(page)
            print(f"👀 AI 看到的上下文:\n{page_context[:200]}...") 

            # 3. 构建 System Prompt
            messages = [
                {"role": "system", "content": f"""
                 你是一个 Playwright 自动化测试专家。
                 这是当前页面的状态：
                 ---
                 {page_context}
                 ---
                 请根据用户的指令，调用 perform_action 工具操作页面。
                 如果找不到元素，请仔细分析 Tree。
                 """},
                {"role": "user", "content": user_prompt}
            ]

            # 4. 调用 LLM
            response = client.chat.completions.create(
                model="gpt-4o",
                messages=messages,
                tools=tools_schema,
                tool_choice="auto"
            )

            tool_calls = response.choices[0].message.tool_calls
            
            result_logs = []
            
            if tool_calls:
                for tool in tool_calls:
                    if tool.function.name == "perform_action":
                        args = json.loads(tool.function.arguments)
                        action = args.get("action")
                        name = args.get("selector_name")
                        role = args.get("selector_role")
                        val = args.get("value")
                        
                        # 5. 执行 Playwright 逻辑 (增加了高亮反馈)
                        try:
                            # 尝试智能定位
                            locator = None
                            if name and role:
                                locator = page.get_by_role(role, name=name)
                            elif name:
                                locator = page.get_by_text(name)
                            elif role:
                                locator = page.get_by_role(role)
                                
                            if locator:
                                # ✨ 视觉反馈：高亮元素
                                locator.highlight() 
                                
                                if action == "click":
                                    locator.click()
                                    result_logs.append(f"✅ 已点击: {role or '元素'} '{name}'")
                                elif action == "fill":
                                    locator.fill(val)
                                    result_logs.append(f"✅ 已输入: '{val}' 到 '{name}'")
                            else:
                                result_logs.append(f"❌ 未找到元素: {name} ({role})")
                                
                        except Exception as e:
                             result_logs.append(f"⚠️ 操作异常: {str(e)}")

                browser.disconnect()
                return {"status": "success", "logs": "\n".join(result_logs)}
            
            else:
                browser.disconnect()
                return {"status": "ignored", "logs": "AI 认为无需操作页面"}

        except Exception as e:
            return {"status": "error", "logs": str(e)}

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
