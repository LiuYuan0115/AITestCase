智能路由与按需提取 (Smart Routing & On-Demand Extraction)
1. 解决接口调用混乱与500错误
问题根源：
目前代码中可能存在“双重绑定”或“兜底机制”。当进入 specialized step (如PRD/TestCase) 时，如果上下文为空，前端逻辑可能错误地回退到了旧的通用 ask 接口，导致同时发送了两个请求，且因为缺少参数导致 500 错误。
修复方案：
彻底解耦：在 App.vue 中，明确 sendPrdAgentMessage 和 sendTestCaseAgentMessage 是唯一入口。禁止在这些步骤中触发通用的 ask 逻辑。
空状态保护：进入函数时，首先检查 currentContext（当前文档内容）。
如果不为空 -> 走修改/分析模式。
如果为空 -> 检查输入是否包含 URL。
如果不包含 URL 且为空 -> 拦截请求，提示用户“请先分析页面或输入目标网址”。
2. 实现“输入URL一键生成” (URL One-Shot)
您提到的“偷偷用iframe”在 Chrome 插件中通常不可行（因为大量网站有 X-Frame-Options: DENY 策略，禁止在 iframe 中加载）。
更优技术实现：后台静默标签页 (Background Tab)
我们采用 “后台打开 -> 注入脚本提取 -> 关闭 -> 发送给AI” 的策略。这完全符合 Chrome 扩展的安全规范，且能渲染需要 JS 的现代网页。
详细执行流程：
用户动作：
用户直接点击导航栏进入 “4.用例”。
在输入框输入：请生成 https://www.example.com/login 的测试用例。
前端路由判断 (App.vue)：
检测到输入中包含 http:// 或 https://。
识别用户意图为 “URL生成模式”。
UI 显示状态：正在后台访问目标页面...。
数据提取 (Background Extraction)：
调用 browser.tabs.create({ url: targetUrl, active: false }) 创建一个不激活的标签页（用户几乎无感）。
监听 tabs.onUpdated 等待加载完成。
注入内容提取脚本（复用现有的 DOM 提取逻辑，但去除复杂的滚动长截图，仅提取 Full Page Text/DOM 和 视口截图，以保证速度）。
提取完成后，browser.tabs.remove(tabId) 关闭该临时标签页。
智能体调用 (Agent Call)：
将提取到的 DOM/Text 伪装成上下文（Context）。
将用户的指令（“请生成...”）作为 Instruction。
调用对应的接口（如 testcase 接口）。
注意：对于 Test Case Agent，如果传入的是 Raw DOM 而不是 PRD，Agent 需要具备直接从 DOM 生成用例的能力（Prompt 中需支持这种情况）。
渲染结果：
后端返回 Markdown 格式的测试用例。
前端直接渲染思维导图，并更新 projectState.documents.testCases。
